# 販売・他の事業所への配布に向けて

GHMS は最初は自社（1法人）で使い、あとで他のグループホームにも販売・配布できるように作っています。
このメモは「すでにできていること」と「売る前に決める・用意すること」をまとめたものです。

## すでにできていること（事業所ごとに変えられる）

| もの | どこで変えるか |
|---|---|
| 事業所名・事業所番号・法人名・住所など | インストーラー／はじめての設定／「設定」 |
| 使う機能（献立表・給与・打刻など）のオン／オフ | 「設定 → 使う機能をえらぶ」 |
| 選択肢（会議の種類・研修の種類など）・独自の項目 | 「設定 → 選択肢を変える／独自の項目」 |
| 実績記録票の列・記号 | 「書類を作る → 実績記録票の項目」 |
| 給与の計算方法（夜勤の払い方・深夜の時間帯・保険料率・最低賃金など） | 「勤怠・給与 → 給与・保険料率の設定」 |
| 実地指導チェックの種類・日数・研修名 | 「実地指導チェック → チェックの設定」 |
| 製品名・販売元・サポートの連絡先・更新の配布先 | `config.ini` の `[product]`（下の例） |

データは各事業所のPCの中（初めは `C:\ProgramData\GHMS\data`。インストールのときに選べる）にだけあり、サーバーは使いません。事業所どうしのデータが混ざることはありません。

```ini
[product]
name = グループホーム業務管理
vendor = 販売元の会社名
support = 0120-000-000 / support@example.com
update_url = https://（販売元の配布先）/latest.json
```

`update_url` を販売元の配布先にすると、その配布先の更新だけを受け取ります（インストーラーに同梱する `config.ini` に書いておく）。

`update_url` の場所（ホスト）と GitHub のリリース（github.com・objects.githubusercontent.com・release-assets.githubusercontent.com）以外からは、更新情報もインストーラーも受け取りません。https でないURLも使いません。

## 更新・データの守り（いまの対策と、残っている心配）

いまの対策：

- 更新情報（latest.json）とインストーラーは https で、決まった場所からだけ受け取る（転送先も確認する）
- ダウンロードしたインストーラーは SHA-256 で確かめ、**起動する直前にもう一度**確かめる
- ダウンロードのたびに、名前の予想できない新しいフォルダ（`C:\ProgramData\GHMS\updates\dl_…`）に置く
- データのフォルダ（`C:\ProgramData\GHMS`）は、管理者・SYSTEM と、インストールした人だけが読み書きできる
  （ほかの Windows ユーザーは開けない）。`config.ini` は管理者だけが書きかえられ、GHMS は読むだけ

残っている心配（売る前に対策する）：

- **インストーラーに電子署名（コード署名）がない**。SHA-256 は「latest.json と同じファイルか」を確かめるだけなので、
  配布先（GitHub のアカウントや latest.json）が乗っ取られると、にせのインストーラーでも確認を通ってしまう。
  コード署名の証明書を取り、インストーラーと GHMS.exe に署名し、更新の前に署名（発行者）を確かめるようにする
- インストールした人と同じ Windows のアカウントで動く、ほかのソフト（ウイルスなど）は、データや更新のファイルにさわれる。
  サーバーのPCは、ふだん使いのアカウントと分ける・ウイルス対策を入れるなど、PCの管理で守る
- ほかの Windows ユーザーでも GHMS を動かすときは、管理者が次のように権限をつける：
  `icacls "C:\ProgramData\GHMS" /grant "ユーザー名:(OI)(CI)M" /T`（データを別の場所に置いたときは、そのフォルダにも同じようにつける）
- 導入作業でまとめて入れるときは `/VERYSILENT /DATADIR="D:\GHMSデータ"` でデータの場所を指定できる
- データの場所をあとから変えるとき：GHMS を止める → データのフォルダごと新しい場所へコピー →
  管理者で `C:\ProgramData\GHMS\config.ini` の `[data] dir` を書きかえる（メモ帳で「ANSI」で保存）→ 起動して中身を確かめてから古いフォルダを消す

## 地域によって変わる初期値（売る前に見直す）

初期値は自社（北海道）の例です。他の地域に売るときは、はじめての設定で都道府県をえらぶ形にするか、導入時に設定してください。

- 健康保険料率（協会けんぽは都道府県ごと）・介護保険料率（全国一律）
- 最低賃金（都道府県ごと・毎年10月ごろ改定）
- 実績記録票の様式（自治体ごとに少し違うことがある）
- 実地指導チェックの回数（自治体の指導内容）

## 売る前に決める・用意すること

1. **利用規約・使用許諾**（何台まで、サポート期間、責任の範囲）。給与・税・保険料・給付費は「概算」であることを明記する
2. **個人情報の取り扱い**（データは事業所のPCの中だけ。販売元はデータを見ない／見る場合の同意）
3. **インストーラーのコード署名**（署名がないとWindowsの警告が出る。証明書を取る）
4. **更新の配布先**（販売元のリリースページ。今は自社のGitHubリリース）
5. **サポートの窓口**と、バックアップ・復元の手順書
6. **ライセンスの確認方法**が必要なら追加する（今は入っていない）
7. 税・社会保険の計算は毎年の改正に合わせて更新を出す体制（料率は設定で直せるが、計算方法の改正は版の更新が必要）

## 自社用の値

自社の決まり（夜勤は深夜手当こみで1回1万円など）は、すべて「設定」に入れています。プログラムの中には書いていないので、他の事業所はそれぞれの決まりに変えられます。

## 打刻のしくみ（今は使っていない・画面に出さない）

自社では打刻をやめ、**管理者が勤務表を組み、その日に「勤務の確定」で「出勤」（勤務表の時間。遅刻・残業は時間を直す）か「休み」「有給」を押す**形にしている（`/work/confirm`）。確定した時間が出勤簿（timecards）になり、給与・有給・実地指導チェックはそこから計算する。体温は職員が自分の画面（`/work/my-health`）で入れる。

事務所のPCで打刻するしくみ（名前を押してPIN・出勤のときに体温、退勤忘れの扱い、打刻のPINのロック）は消さずに残してある。販売先で打刻を使いたいときは：
- データベースの settings に `attend_mode = punch` を入れる（画面にはまだ切りかえを出していない。出すときは「設定 → 事業所の設定」に選択肢を足す）
- 打刻の画面：`/work/kiosk`（PINの端末として登録した事務所のPCだけ）、ログインした職員は `/work/clock`
- コード：`ghms/work.py` の `punch_mode()`・`punch()`・`kiosk()`・`clock()`、テンプレート `work_kiosk.html`・`work_clock.html`、テストは `use_punch(app)` を使っているもの
- 打刻のときは「勤務の確定」の画面・今日のやることの「勤務を確定する」は出ない（`hubs.py` の5つ目の値、`today.py`）
